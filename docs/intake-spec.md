## 1. The flow

Entry: post-signup, after Tier 0 (birth data → ghost sky) or skipping it (no chart → intake begins on an empty-but-fringed sky; both paths first-class). Seven prompts, one screen each, in order:

1. **A shaping moment** — "Tell me about a moment that shaped how you move through the world."
2. **A repeated pattern** — "What's something you notice yourself doing again and again?"
3. **What you'd protect** — "If everything else were negotiable, what would you protect?"
4. **What people misunderstand** — "What do people most often get wrong about you?"
5. **Key relationships** — "Who matters most, and what are you like with them?"
6. **What you're proud of** — "What have you done or become that you're quietly proud of?"
7. **Who you're becoming** — "Who are you in the middle of becoming?"

(Prompt copy is versioned config — `intakePromptsVersion` — and oral-history-crafted per CORE-07: open, concrete, second-person warm. Exact wording is editorial; Jacob's ear passes it like the lens labels. **Publishing process (v1.1):** every prompt-config change passes an editorial checklist before its version ships — no wound-origin phrasing, no diagnosis-adjacent language, second-person warmth — a documented human gate, deliberately process-not-code.)

**No wound-origin questions, ever** (§5.1 rule). The sparks open real material by invitation, not excavation.

## 2. Per-answer mechanics (the consequence loop)

Each answer → one `SourceEvent` with **`kind = INTAKE_SPARK`** (v1.1 — the "intake tag" is this kind, already present in the schema enum and in the pass entry point's kind allowlist; nothing else marks intake-ness for extraction purposes), `authorship = SELF` → crisis floor (§2.2) → **immediate reflect** (intake is the sanctioned exception to batched extraction — the batching rule exists for cost/calm; intake's whole pedagogy is immediacy; cap: 7 passes/session, the prompts ARE the cap) → the between-screens beat (§2.4) → the next prompt.

**The orchestration surface (v1.2):** one server action per spark submission — save → classify → reflect-or-defer → beat composed from the veiled projection — is the single surface tests 3, 9, 10, and 11 target. The keystone tests aim at a real seam, not UI glue.

**Extraction mode (v1.1):** intake runs under whatever `livePolicyFor` derives — SOLO for a fresh signup, PRACTITIONER_SUPPORTED for a pre-verified client in the wedge flow (master concept §6.2). Both are in-scope; §2.4's veil rule exists for the supervised case.

**Skippable, always:** every prompt has a visible, unpenalized "skip this one." Skipping writes **no SourceEvent and no content**; it writes only the session-state mark (§6.1) that lets the spark be re-offered later. The intake never pressures disclosure (LAW 6: no scoring of depth).

### 2.1 Concurrency & ordering (v1.1 — the loop's integrity contract)

The real entry point (`runExtractionPass`) processes *all* un-extracted sources since the last complete run and returns a per-run summary. Called at intake cadence without a contract, that corrupts:

- **One in-flight pass per user, enforced at the shared entry point (v1.2).** "One utterance counts once" is a property of the user's extraction stream, not of the intake flow — journal `reflectNow` calls the same entry point, and a user mid-intake with the journal open in another tab (fully plausible under §6.2's re-run flow) can race an intake pass from outside intake. The guard therefore lives in/at `runExtractionPass` for **every** caller: a partial unique index on `ExtractionRun(userId) WHERE status = 'running'` (raw-SQL migration, house style; a Postgres advisory lock is the noted alternative, decided at build) — a second concurrent pass fails fast deterministically. **Staleness reaper (v1.3; simplified at diff verification):** a `running` run whose `startedAt` is older than `intake.reflectTimeoutMs` + `intake.runReapGraceMs` (named, versioned) is reapable; the **next caller** reaps it before creating its own run — no daemon. Under §2.3's abort boundary the reap is simple by construction: **the reaper always reaps to `error`** — a `running` row with committed mutations is unrepresentable (the `complete` flip commits inside the writer's transaction), so an observed stale `running` row has, by construction, written nothing. The reap is a **conditional update (`WHERE status='running'`)** that loses cleanly to an in-flight completion racing it, and `intake.runReapGraceMs` is explicitly sized to bound the post-checkpoint stage (writer + matcher) so a live-but-late pass is never reaped mid-commit. A crash-orphaned row therefore can never become a permanent lockout (test 9 pins reap-to-`error`). The intake UI additionally disables spark N+1's submit until spark N's beat resolves, but that is UX, not the enforcement. **Submission idempotency (v1.3):** one utterance counts once at source creation too — spark submission is idempotent under a server-enforced uniqueness on (session, sparkIndex); a double-tap or network retry coalesces deterministically to the first event, never minting a duplicate (test 17). Overlapping passes double-extract the same utterance, and double-extraction is not duplicate work — it is **forged recurrence**: `timesSeen` inflated past the materialization threshold by a race, a node minted from a single mention. The keystone test (§8, test 9) asserts exactly this stake, at the entry-point level, including the cross-surface case.
- **The watermark window is fixed in `run-pass`, failing-first:** the run row is created *first* and sources load against its own `startedAt` — the current load-before-create sequence strands any event ingested in the window (ineligible for every future pass: silently unmapped words). This is a correctness bug in the shared entry point, fixed there (not intake-side), with its own regression test; the journal inherits the fix. **Zero-source-run semantics (v1.2, stated):** create-first means a run row can exist with zero eligible sources; a zero-source run is marked `complete` and advances the watermark — it verified emptiness as of its `startedAt`, which is correct, and the regression test covers the empty case (the journal's "nothing new to reflect on" copy path depends on it).
- **Merged-pass honesty (carrier corrected v1.2).** A failed or aborted pass does not advance the watermark, so the next pass may cover more than one answer. When a pass covers >1 source, the beat **must say so** — "catching up on your last two answers…" — and must never attribute the merged delta to the single answer just given. Carrier: **`RunPassResult.sourcesExtracted > 1`** — the run's own result, not the pre-read count (`countUnextractedSources` is TOCTOU-racy against other tabs and blind to the per-run cap; `sourcesDeferred` covers the capped remainder honestly). The pre-read count survives only for pre-pass waiting copy. Answer N's stars belong to answer N's beat, or to an honestly-labeled catch-up — never to answer N+1.

### 2.2 The crisis floor (ingest contract, named)

The crisis classifier runs on **every answer, unconditionally** — before extraction, never gated by mode, veil, or session timing. Intake reuses the journal ingest pattern (`app/(sky)/journal/actions.ts`, order corrected v1.2 to match the code as it actually is): **classify synchronously → persist the event with the verdict embedded in the create's `signals.crisis`** (term keys, level, versions — never the person's words) **→ beat only after the verdict → then and only then extraction.** Classify-then-persist is load-bearing, not cosmetic: the event is immutable, so the verdict has no legal carrier post-create, and persist-first opens a crash window holding an unclassified entry. (`signals.crisis` on intake events coexists with §6.1's rule — the crisis verdict IS a signal; intake-*meta* is not, and stays out of `signals`.) Intake's own additions:

- **The beat never renders before the crisis verdict.** The verdict is serial and blocking; its latency is inside §2.3's budget.
- **On a CRISIS-level answer:** the intake **pauses** into the resource surface calmly; the entry still saves (the words are never lost); the reflect pass for that answer is **deferred, and its delta celebration is suppressed** — "I heard two things — one brightened a star" immediately after active ideation is a concrete failure of the calm this product promises. The remaining sparks wait; on resume, the deferred material rides the next pass under §2.1's merged-pass copy rule.
- Classifier failure posture is the classifier's own (fail-closed on soft-signal + model failure); intake adds nothing and removes nothing. **One gap closed at the source (v1.3):** the classifier's model-arbitration call gains a named timeout in **crisis config** (`crisis.modelArbitrationTimeoutMs`) — expiry = model failure, dropping into the existing fail-closed rules (soft-signal → CRISIS; no signal → NONE; `degraded: true` recorded on **both** timeout branches, LAW 5's honest carrier). Classification always terminates; persist always proceeds; a hung provider can no longer block the one path that must never block. The journal inherits this free — the fix lives in the classifier, not intake. Test 3 carries the hung-arbiter case (below).
- **The fork's carriers are named (v1.3):** the CRISIS path is driven by a `celebrationSuppressed` flag on the beat's view state (deterministic from the verdict — the beat template cannot render a delta line while it is set) and a resume token on `IntakeSession` marking the paused spark; both live at the server/UI boundary the orchestration surface owns. `signals.crisis`'s minimal shape is typed and validated at ingest: `{ level, method, matchedTermKeys, classifierVersion, lexiconVersion, degraded, checkedAt }` — the fields the journal already writes, documented as the contract.

### 2.3 Latency budget & failure posture (v1.1)

The beat sits on a crisis verdict + a full model round-trip with an unbounded tail. Named budget: **`intake.reflectTimeoutMs`** (versioned config). The waiting state is designed, not accidental: the sky glimpse may *start* (settle animation on the existing sky) while the pass runs, resolving into the delta — or into honest copy.

**Timeout is not failure, and v1.2 makes them converge: abort-on-timeout (ruled).** A timed-out pass still running server-side that later *completes* would advance the watermark with no beat narrating it — the fold-forward copy would lie and answer N's stars would land attributed to nothing. So on timeout the orchestrator **aborts the pass server-side and marks the run `error`**: the watermark holds and the fold-forward copy is true by construction. Aborted ≠ lost — the event persists and the material genuinely folds into the next pass; attribution integrity outranks throughput. A submit arriving while a timed-out pass is still unwinding is **rejected into the waiting state** (the §2.1 entry-point guard makes a second concurrent run structurally impossible); it proceeds when the abort lands.

**The abort boundary is the writer's transaction (v1.3, ruled — the general principle).** Abort is honorable **only before the write stage**. Once the writer's transaction begins, the pass runs to completion — and the run's `complete` status flip commits **inside that same transaction**, atomic with the graph mutations. One atomic truth **over the writer's mutations and the run status** (scope stated honestly, v1.3 diff verification): an abort (or crash) can never yield `status = error` with graph mutations already committed — the path that would re-extract the same sources and hand forged recurrence its fourth entrance. The status flip carries the run-row's completion fields (`promptVersion`, `contractVersion`, `attempts`) with it. **The matcher sits outside this atomicity, deliberately:** it runs in its own transaction after `complete`, and a crash between the two is *recoverable by construction* — every matcher run recomputes against the FULL standing hypothesis and extracted sets (verified: the matcher loads all of both, not per-pass deltas), so the next pass's matcher heals a skipped one; only that answer's `ghostsCharged` narration is late, never lost. A pass that crossed the boundary before the timeout narrates as an honestly-labeled catch-up (late ≠ aborted; the reject-into-waiting posture covers the UX). This also closes the pre-existing crash window in `run-pass.ts` between writer-commit and status-update — the same double-extraction bug with no timeout needed. (Test 10's race case: abort raced against the write stage yields either `complete` + narrated or `error` + zero graph mutations — never `error` + mutations.)

**Budget scope (v1.3):** `intake.reflectTimeoutMs` starts at **pass start, post-persist** — the classify stage sits outside it (its own bound is the classifier's `crisis.modelArbitrationTimeoutMs`, §2.2), so "the event persists" is true by construction of the budget's own scope.

On abort or a thrown pass: **"that one's saved — I'll keep listening as we go"** — the material folds into the next answer's pass (§2.1 merged-pass rule), never a silent skip, never a blocking retry, and the proposer spec §10.5 backoff-notice machinery never surfaces mid-flow. **A failed reflect never blocks progression to the next spark.** The words are safe in the event store; immediacy is the pedagogy, not the integrity.

### 2.4 The between-screens beat (copy provenance pinned)

A one-line plain-language result + a 2–3s sky glimpse animating the delta, then the next prompt.

- **Deterministic templates only.** Beat and reveal copy are composed by deterministic templates over pipeline results (`ReflectSummary`, `matcher.transitions`). No model-authored copy anywhere in intake v1.
- **Identities come from the veiled projection.** Any node/ghost identity the copy or glimpse names is drawn from the veiled `SkyViewModel` (renderer-lens v1.3: the veil is a property of the projection), **never** from raw `GateResult`/`MatcherRunResult`. A supervised-mode intake answer that extracts a WOUND renders the veil copy in the beat — never the label (§8, test 11).
- **Copy branches by what actually happened**, so no line can claim what didn't: `linksCreated > 0` → "…brightened a star your chart placed" (impossible for a chartless user by construction — **but note the dependency, v1.2:** this implication holds only while the hypothesis matcher is LENS-only; `ReflectSummary.linksCreated` carries no provenance, so matcher expansion (§7.1 bundle) obligates provenance-discriminated counts before this line survives it); else `materialized > 0` → "…lit a new star"; else `forming > 0` → "…one is forming at the edge"; else rejected-only → honest not-yet copy. **Zero-change split (v1.1):** `forming > 0` → "held onto that — it'll take shape as themes recur"; all-zero → "saved — nothing new took shape from this one yet" (nothing was "held" in any graph sense; the copy doesn't pretend otherwise).
- **Reduced motion:** under `prefers-reduced-motion`, the beat is the text result + a static sky diff (or list-view delta) and the reveal drops the slow settle — the renderer-lens accessibility contract does not lapse in the first ten minutes. **The static diff's derivation (v1.3):** computed from the veiled `SkyViewModel` before vs. after the pass — same source as the animated glimpse, parity asserted in test 15; never a separate code path that could drift from the veil.
- **Renderer warmth:** the sky renderer pre-warms at intake start behind a pre-ready skeleton; the list view is the always-warm fallback.

## 3. Voice (the hero path, honestly hedged)

Voice-first: tap-to-talk, browser Web Speech API, live transcript visible AS the person speaks, **editable before submit** — the person always reviews and owns the words that become evidence (the OCR-review principle from IDEA-018 applied to STT: transcription errors must not become "their exact words" unreviewed).

**Two-stage submission, structural (v1.1):** the STT stream fills a client-side buffer only → the person reviews/edits the draft → explicit Submit writes `SourceEvent.content`. Raw STT text is never persisted server-side and never reaches crisis classification or extraction pre-review; the submitted content byte-equals the reviewed draft (§8, test 4 asserts both halves).

**The honest privacy claim (v1.1 reword):** *we* never store audio; only the reviewed transcript becomes the SourceEvent. The browser Web Speech API itself may transmit raw audio to the browser vendor's cloud for recognition — a third-party transit this product does not control and does not hide; the STT provider's data-handling terms are a named pre-pilot governance item (master concept §7.1). Text entry is the co-equal fallback, one tap away, no mode shame. Per the cut-line (§7 item 1): if rehearsal in a noisy room degrades voice, text-first with voice as the try-it path is the fallback posture — a config flip, not a rebuild.

## 4. The seventh spark and the becoming lane

Spark 7's answer extracts normally (words about becoming are still words). But BECOMING nodes are **authored intentions, never extractions** (lane ownership, absolute). After spark 7's reflect, the intake offers — explicitly, consentfully: *"Would you like to place this as a seed on your sky — a quality you're becoming, that your future words can ignite?"* with a one-line editable seed statement drafted from their answer. Accept → a BECOMING node via the becoming lane. Decline → nothing; the extraction stands alone. The seed moment is the intake's closing ceremony.

**The becoming lane (v1.1 — this spec owns the seam contract; ruled, option (a)):**

- **The lane is THE becoming lane, not intake's** — `/src/engine/becoming/`, with the future becoming-design UI (master concept v1 IN #4) as its second caller. Nothing intake-specific lives in the lane itself; intake passes it the accepted statement and provenance stamps, nothing more.
- **Fourth sanctioned writer computer.** The schema banner ("exactly THREE sanctioned upstream computers") is amended — a named schema delta in the same build commit that creates the lane — to list the becoming lane as the fourth. The banner did its job in review (a forbidden write path was findable by reading); the amendment keeps it able to do that job.
- **The declaration is an inbound entry and passes the crisis floor (v1.2, ruled — round 2's Critical, ours):** the seed statement is person-*edited* SELF text, and LAW 7 covers every inbound entry, not just answers. The declaration write routes through the same ingest step as everything else: classify → persist with the verdict in `signals.crisis` (§2.2's order). **On a CRISIS verdict the seed still plants** — the ceremony completes *without celebration* and the resource surface engages calmly, same posture as §2.2. Silence the fanfare, never the person. (Test 13.)
- **The declaration carrier:** the accepted seed statement is written as its **own `SourceEvent`, new `SourceKind.BECOMING_DECLARATION`** (schema delta, owning migration named in the build). The BECOMING node (provenance BECOMING, `state = HYPOTHESIS`, mass 0) carries one Evidence row citing that event's **full span verbatim** — deterministic validation (the quote is the whole content; a check that cannot fail is stated as such, same honesty rule as the lens lane's gate exemption).
- **Not extraction-eligible, pinned (v1.2 — both lanes independently):** `BECOMING_DECLARATION` never enters the extraction pass — it is a ceremonial carrier whose themes were already extracted from spark 7's answer; letting it in would count one utterance twice (§2.1's forged-recurrence stake through §4's side door). The pass kind-allowlist excludes it *deliberately*, and a regression test pins the exclusion against the future "why is this SELF event never extracted?" cleanup. (Test 14.)
- **One transaction, or nothing (v1.3 — the third round's becoming seam, the last one):** `writeBecomingDeclaration`'s transaction spans **all four rows** — the `BECOMING_DECLARATION` SourceEvent create, the node, the evidence, and the intake-meta row. Crisis classification runs *before* the transaction (§2.2's order; the verdict rides the create). This is load-bearing because the declaration is the one SELF text with **no fold-forward path by design** (extraction-ineligible, above): a crash between persist and node-write would strand an orphan no later pass can ever redeem — so the partial state is made unrepresentable. Mid-ceremony failure ⇒ zero becoming artifacts *including the event*, retryable; success ⇒ all four rows (test 5).
- **The declaration's meta row (v1.3, shape defined before the migration guesses):** `sparkIndex` is a `DECLARATION` sentinel (not a spark), `inputMode = EDITED_DRAFT` (it is neither reviewed voice nor typed-fresh), and `becomingSeedTemplateVersion` is required on exactly this row.
- **The writer's door (v1.2):** the lane writes through a named writer-side entry point — **`writeBecomingDeclaration`** (deterministic, transactional; the writer remains the sole author of graph state). The same build commit that amends the schema banner amends the writer's own header and its `validated: true` "set ONLY here, ONLY for gate output" comment to name the becoming lane's declaration path — the comments that made round 1's catch findable stay able to do that job. Test 5 additionally asserts the artifacts were written by the writer path and no other module holds the insert.
- **Born unable to self-ignite (ruled constraint i):** the declaration evidence is created `role = DECLARATION` — non-conferring under the standing allowlist rule (`SUPPORT | ENACTMENT` confer; BECOMING ignition requires ENACTMENT only). Mass 0 at birth, structurally: the lane cannot charge the node it creates, no matter what copy or code calls it. Ignition comes only from future lived words through the gate.
- **The drafting template is deterministic and versioned (ruled constraint ii):** **`makeSeedDraft(answerText, version)`** — a pure function under `becomingSeedTemplateVersion`, a named transform over the spark-7 answer (no model call, no free prose); the version is stamped on the declaration's intake-meta row. The draft is a *suggestion rendered from their words*; the person's edit is the statement. What is persisted is exactly what they accepted, byte-for-byte.
- **Consent is the only path:** no accept → no SourceEvent, no node, no evidence, zero becoming artifacts (§8, test 5).

## 5. Stopping rule & the reveal

Target: **7±2 evidence-bearing objects**. **The counting predicate (v1.1, computable):** `COUNT(EXTRACTED nodes, archivedAt IS NULL)` + `COUNT(node-kind ShadowCandidate rows)` + `COUNT(hypothesis-provenance nodes WHERE EXISTS(active HypothesisEvidenceLink))` — the charged-ghost predicate **imported from the renderer's definition, never restated**. (Chosen explicitly: a CONTRADICTED mass-0 ghost still counts — being shown wrong is sky-worthy; that is the product's claim.) Pure hypotheses (uncharged ghosts) don't count.

**Named config (versioned), each with its consumer (v1.2):** `intake.targetObjects` (7 — consumed by the reveal's summary copy, which calibrates against it: "a beginning sky of about seven"), `intake.earlyCloseBound` (9 — drives the early-close offer), `intake.minPromptsBeforeClose` (4 — floor guard in the state machine). A named key nothing reads is the inverse of the no-magic-numbers rule. If the count reaches `earlyCloseBound` before prompt 7, offer an early graceful close ("your sky has plenty to begin with — the rest of the sparks will wait for you"); never before prompt `minPromptsBeforeClose`. After the final spark (or early close): the **reveal** — full-screen sky, slow settle (reduced-motion per §2.4), the summary of everything heard (deterministic template, veiled projection — §2.4's rules govern the reveal too), and the standing invitation into the journal loop. The reveal is the demo's money shot; it gets the ceremony styling budget.

## 6. Session mechanics

### 6.1 Schema & carriers (v1.1)

- **`IntakeSession`** (owning migration named in the build): `id, userId, status (IN_PROGRESS | COMPLETED | EARLY_CLOSED), currentPrompt, intakePromptsVersion, startedAt, finishedAt?`, plus per-spark status rows or embedded array: `sparkIndex, state (PENDING | ANSWERED | SKIPPED), sourceEventId?` (the answering event, when answered). The skip mark lives here and only here — no content, no timestamps-of-hesitation, nothing scoreable (LAW 6/8).
- **Event-side stamps — the carrier named (v1.2; shape completed at diff verification):** **`SourceEventIntakeMeta { sourceEventId PK/FK, sparkIndex Int? (NULL = the declaration's DECLARATION sentinel), intakePromptsVersion, inputMode (VOICE_REVIEWED | TYPED | EDITED_DRAFT), becomingSeedTemplateVersion? (required exactly when inputMode = EDITED_DRAFT) }`** — a side table with its own owning migration, same treatment as the other two schema deltas. **A-6's uniqueness carrier lives on the session side:** unique `(sessionId, sparkIndex)` on the `IntakeSession` per-spark state row with `sourceEventId` set-once; the §6.2 re-run flow *reuses* the spark row (SKIPPED → ANSWERED updates in place, linking the new event), so answering a previously skipped spark inserts cleanly and never collides. Explicitly **not** `SourceEvent.signals` (documented corroboration-signal space; not quietly overloaded — the crisis verdict, which IS a signal, stays in `signals.crisis` per §2.2). Which prompt wording elicited which answer is reconstructable forever (version-everything invariant), and editorial changes never alter historical events.
- **Per-prompt yield telemetry (LAW-6-safe by construction):** incremental aggregate counters keyed (`intakePromptsVersion`, `sparkIndex`) only — pass yield (heard/forming/rejected), skip rate, early-close rate, per-session pass count (structurally ≤7, logged on the session row). Never per-person rows, ever; this must never become disclosure-depth scoring, and saying so here is what keeps it structural.

### 6.2 Resume & re-run

Resumable: `IntakeSession` persists current prompt + per-spark state; abandonment mid-intake is fine and resumes where left (§8, test 8: kill at every prompt boundary). Re-runnable: completed intake can be revisited to answer skipped sparks (events append; nothing re-asked that was answered — the ANSWERED mark is the guard). Total time target: 8–12 min voice, comparable typed (inside master concept §5.1's ~10–15 envelope). Every screen: calm, one action, generous whitespace — the §9 "first ten minutes flawless" bar applies to THIS module above all.

## 8. Tests

1. **Pipeline reuse keystone:** an intake answer flows through the REAL wrapper→gate→writer→matcher path identically to a journal entry (zero intake-specific extraction code paths; the only differences are `kind = INTAKE_SPARK` — asserted — and immediacy).
2. **Skip is data-free:** skipped prompt → no SourceEvent, no pass, no content anywhere; only the IntakeSession spark-state mark exists.
3. **Crisis pause:** a crisis-level answer pauses the flow into resources; the entry still saves; **the beat never renders before the crisis verdict, and a CRISIS answer renders no delta celebration**; remaining sparks resume later, deferred material under merged-pass copy; **the persisted event carries the verdict in the create's `signals.crisis` — no persisted-but-unclassified row is ever observable (v1.3)**; **plus the hung-arbiter case (v1.3 diff verification): a stalled model-arbitration call terminates at `crisis.modelArbitrationTimeoutMs` into the fail-closed rules, the verdict persists in the create with `degraded: true`, and the flow proceeds — classification always terminates.**
4. **Transcript ownership:** the submitted SourceEvent content byte-equals the reviewed/edited transcript; **raw STT text is never persisted server-side and never reaches classification/extraction pre-review**.
5. **Becoming consent:** no BECOMING node exists without the explicit accept; the seed statement is the person's edited words byte-for-byte; the declaration evidence is `role = DECLARATION` and the node's mass is exactly 0 post-ceremony; decline leaves zero becoming artifacts; **the artifacts were written by `writeBecomingDeclaration` and no other module holds the insert (v1.2)**; **mid-ceremony failure leaves zero becoming artifacts *including the event*, retryable; success writes all four rows in one transaction (v1.3)**.
6. **Stopping rule:** counts computed by the §5 predicate trigger the early-close offer at `intake.earlyCloseBound`, never before prompt `intake.minPromptsBeforeClose`; asserts against the config keys — **including `intake.targetObjects`' consumer: the reveal copy calibrates against it (v1.3)**.
7. **Both entries:** chartless intake works end-to-end (no lens dependency anywhere; the chart-copy branch is unreachable chartless).
8. **Resume integrity:** kill mid-intake at every prompt boundary → resume lands on the correct prompt with prior answers intact.
9. **The forged-recurrence keystone (restated entry-point-level, v1.2):** concurrent pass attempts — including the **cross-surface case** (journal reflect fired during an intake pass) — are refused by the entry-point guard: exactly one run proceeds; **no source extracted twice** (one utterance counts once — `timesSeen` never inflated by a race; a node can never materialize from a single mention via overlap); **no source stranded** by the watermark window, including the **zero-source-run case** (empty run completes and advances honestly); answer N's delta narrated in answer N's beat (or an honestly-labeled catch-up), never attributed to answer N+1; **plus the orphaned-row case (v1.3): a crashed `running` run is reaped by the next caller per §2.1's staleness rule — recovery proceeds, nothing stranded, nothing double-extracted, no permanent lockout.**
10. **Merged-pass honesty:** a failed pass followed by a new answer → one pass covering both, and the beat renders catch-up copy (keyed on `sourcesExtracted > 1`), never single-answer attribution; **plus the timed-out case (v1.2): a pass aborted at `intake.reflectTimeoutMs` is marked `error`, its material verifiably folds into the next pass, and no sky change ever lands un-narrated; plus the abort-boundary race (v1.3): an abort raced against the write stage yields either `complete` + narrated or `error` + zero graph mutations — never `error` + mutations. Scope honesty (diff verification): sky changes are **never mis-attributed**; a late delta surfaces honestly (late beat, catch-up, or the reveal) — never as answer N+1's.**
11. **The veil holds in the beat (v1.1):** supervised-mode intake answer extracting a WOUND → the beat/reveal render veil copy from the veiled projection, never the raw label.
12. **Spark-shaped eval fixtures:** ≥7 hand-labeled spark-answer fixtures (one per prompt, incl. one thin answer and one rambling voice-style transcript) live in the eval corpus **before the intake build starts**; fidelity scored over the genre the demo actually runs on.
13. **The declaration passes the floor (v1.2):** a crisis-phrased seed statement is classified and flagged like any entry; the seed still plants; the ceremony completes **without celebration** and the resource surface engages.
14. **Extraction-ineligibility regression (v1.2):** `BECOMING_DECLARATION` is not in the pass kind-allowlist and never reaches the proposer or gate — pinned against future allowlist edits.
15. **Reduced motion (v1.2):** under `prefers-reduced-motion`, the beat renders text + a static diff, the reveal drops the settle animation, and the list-view delta matches the view model — **static diff derived from the veiled `SkyViewModel` before/after, parity with the animated path asserted (v1.3)**.
16. **Meta stamps (v1.3 — the tripwire's carrier):** every answered spark's SourceEvent has a `SourceEventIntakeMeta` row with correct `sparkIndex`/`intakePromptsVersion`/`inputMode`; the declaration's row carries the `DECLARATION` sentinel, `inputMode = EDITED_DRAFT`, and `becomingSeedTemplateVersion`; a skipped spark has none (pairs with test 2).
17. **Submission idempotency (v1.3):** double-tap / retried submit of the same spark coalesces to one SourceEvent under the (session, sparkIndex) uniqueness — never two events for one utterance.
