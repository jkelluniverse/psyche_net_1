## 1. The lens lane (`/src/engine/lens/`)

**What it is:** birth data → astrology-api.io → `ChartImport` row (raw JSON preserved) → a **deterministic, versioned mapping** produces lens `PsycheNode`s: **domain-typed** (D-R4: a lens hypothesis about a protection is `type=PROTECTION, provenance=LENS` — never `type=LENS`, which is deprecated-never-written and rejected by DB CHECK), `state=HYPOTHESIS`, `mass=0`, `confidence=` the hypothesis floor (0.15, config), `chartImportId` FK set, `lensMapVersion` stamped.

**The mapping is code, not model.** A versioned table (`lens-map.v1.ts`) from chart features (e.g., HD type/authority/defined centers; natal placements) to hypothesis node templates — each with a **domain `type`**, a plain-language label ("may protect independence under pressure"), an `ontologyKey`, and a `priority` (integer, for the ghost budget). Same chart → same ghosts, always. No LLM anywhere in this lane; an LLM summarizer for chart *prose* is post-pilot and would never create nodes regardless (LAW 4 applies to lanes too: only the mapping creates, and only lived words ever charge).

**The ontology direction rule (D-R1 — this is what keeps the blinding invariant untouched):** the shared ontology is **chart-agnostic, and the lens map projects into it.** Lens-map targets must be existing psychological keys (e.g. `protection.independence`); **no chart-specific key ever enters the ontology the proposer sees.** Under this rule the proposer sees the same global vocabulary for every user, chart or no chart — a global vocabulary is not a hypothesis, so nothing user-specific can leak. The residual gradient is population-level (the ontology slowly growing chart-shaped), and it is *measured*, not assumed away: the eval corpus carries a lens-confirmation case (§5 test 9) whose match rate is tracked per ontology version.

**Rules:**
- v1 systems: Human Design + Western natal (or HD only if the API integration fights back — cut-line applies). `system` recorded per import.
- **Ghost budget:** a chart can imply dozens of hypotheses; cap materialized ghosts (config key `lens.ghostBudget`, ~9–15) ranked by a **total order: priority desc, then ontologyKey asc, then label asc** (applied before the cap — ties can never make the determinism test flaky). An overcrowded ghost sky is noise and undermines the "few honest hypotheses" posture.
- **Idempotency is structural, not aspirational:** imports are keyed by a canonical `chartFingerprint` (hash of normalized birth inputs + resolved timezone + provider id — never the provider's JSON bytes, whose field order is not ours), with `@@unique([userId, system, chartFingerprint])`. Re-import of the same chart upserts; lens nodes upsert by `(userId, provenance=LENS, ontologyKey)`. A `lensMapVersion` bump re-runs the mapping: unchanged keys update in place, removed keys archive their **uncharged** ghosts, and CHARGED ghosts (any validated evidence linked via §3) are never auto-archived — they sever gracefully per §7's cascade rule. This mirrors the gate spec's shadow-rekey duty.
- Birth data is quasi-special-category PII (schema comment): transported to the chart API over TLS, raw response stored, provider + retention now logged in the §7.1 governance bundle (the entry exists as of this version; the architecture it names is pre-pilot work).
- Birth-data **intake** (the form on a phone, validation, timezone resolution) is app-layer work owned by the intake module, not this spec; the seam contract: intake delivers `{birthDate, birthTime, birthPlace, tzResolved}` validated; the lane owns everything after.
- **No lens node is ever created from extracted text**, and no extracted node ever gets `provenance=LENS`. The lanes never cross except in §3 — and, since gate v1.7, not even the gate's dedupe can cross them (test 19 pins it).

**Failure modes:** API down/malformed → import recorded with `ChartImport.status=error`, zero nodes, retryable — never a partial ghost sky. Unknown chart feature → skipped and logged, never guessed into a node.

## 2. The renderer (`/src/app/(sky)/` + `/src/engine/sky-projection/`)

**Data flow:** persisted graph → `skyProjection(nodes, edges, now, seed, config)` (pure function → a `SkyViewModel`) → cosmos.gl v3. The projection is the ONLY place domain values become visual values, and it is unit-testable without a GPU. `seed` is explicit (= stable hash of userId); `config` is the versioned renderer config; the emitted view model carries `projectionVersion`. **Honest determinism boundary:** the VIEW MODEL is deterministic (same inputs → same view model, test 4); GPU force-layout positions are NOT reproducible across devices/drivers even with a fixed seed — demos must never claim "the same sky every time," only the same *content*.

**Structural input honesty:** the projection's input types are persisted views only (`PersistedNodeView`, `PersistedEdgeView`); `ShadowCandidate[]` is type-level unrepresentable as projection input. Shadow-lane material is held, not shown — enforced by the type system, not convention.

**The rendering grammar (each mapping versioned in `rendererConfig`, per the physics grammar §4.4):**
- `mass` → node size (log scale; mass 0 = minimum ghost radius).
- **Brightness** → a **named, versioned recency function** `brightness(evidence.occurredAt[], now)` (half-life in config) computed inside the projection from evidence timestamps and the explicit `now`. The persisted `luminosity` column is **not consumed** — its defining formula is still deferred per the schema's own guard, and this spec does not compute it ad hoc. DORMANT nodes dim, never vanish.
- `confidence` → **always visible** (LAW 5): opacity floor + a subtle uncertainty ring (band constants in rendererConfig); low confidence must be *legible*, not just technically encoded. **Edges too:** edge `confidence` maps to opacity/dash treatment (versioned config) — a thin low-confidence PROTECTS_FROM edge must be visually distinguishable from a well-evidenced one.
- `state` → styling: HYPOTHESIS = **ghost styling** (dashed ring, reduced saturation, explicit "hypothesis" badge on tap — the ghost sky's entire integrity claim is that it *looks* like a question, not an answer); CONTRADICTED = visibly dimmed/struck, still present; IGNITED = the ceremony style; QUESTIONED/LOOSENING per the change arc.
- **WOUND gating (D-R5, completing D9 at the display layer):** WOUND-type nodes render **veiled-but-present** in INDIVIDUAL skins (LAW 5: never falsely complete; LAW 7: never raw at 1 a.m.) — full visibility in supervised skins per consentScope. The veil's register is everything: copy is calm and forward-looking ("something to explore together next session"), never ominous; veiled nodes render **singly, never as a clustered mass**; the crisis classifier's operation is fully independent of the veil. Gating lives in versioned config (`rendererConfig.woundGate`); if veiled presence proves anxiogenic in pilot, the fallback is practitioner-release-only visibility — a config change, not an architecture change (§7.1 pilot-feedback item).
- Edges → line weight by strength, style by type; shadow-lane edges are **not rendered at all** (structurally excluded, above).
- **Matched pairs render LINKED, never merged and never as two unrelated stars:** after a §3 match, the extracted node and the charged lens ghost render with an explicit link/badge relationship (grammar-specified) so one construct never reads as two bodies.
- The **edge of the unexplored** (LAW 5): the sky always renders a soft unexplored fringe — defined as an honest static affordance (config-owned copy + treatment; v1 does not pretend to compute "how much is unexplored"), so it can never degrade into a decorative vignette that falsely implies measurement. Never blank, never falsely complete.

**Hard invariants (from CLAUDE.md — restated because this module is where they bite):**
- **Domain/rendering separation:** force-layout positions are stochastic artifacts. No coordinate is persisted into domain state, read as meaning, or fed back into anything. **Migration 6 dropped `PsycheNode.x/y/colorHint`** — the columns that contradicted this rule; test 5 now asserts at the schema level that no coordinate columns exist on domain tables. Layout uses the fixed per-user seed for session-to-session visual continuity — a *rendering* convenience, not a semantic claim; any future layout cache lives in a rendering-only store keyed by node id, never on domain tables. Nothing in copy or UI may imply proximity = psychological relatedness beyond the edges actually drawn.
- **cosmos.gl v3 only** (`@cosmos.gl/graph`, MIT; never `@cosmograph/cosmograph`): async init — constructor returns immediately, public methods queue until `graph.ready`; use the v3 API, no pre-v3 tutorial code. Pin the version in the lockfile; record the SPDX license at install; an integration test covers the queue-until-ready seam.
- **Reduced-motion / non-spatial fallback:** `prefers-reduced-motion` → static layout, no animated transitions; plus a full **list view** — nodes AND edges grouped by type/state, keyboard navigable, evidence accessible — **shipped inside the ghost-sky milestone** (A-9: it is v1-mandatory because position carries no domain meaning, so no information may exist *only* spatially or in motion; a demo without it violates LAW 5). The list view is the **canonical accessible surface** (screen readers get nothing from a WebGL canvas) and is content-parity property-tested against the same view model.
- **Mobile touch is first-class** (the demo is on their phone): tap = select, pinch = zoom. Evidence has an **explicit affordance in the node panel** (tap → select, tap again → details); long-press remains a secondary path, never the only one (iOS long-press conflicts with OS gestures). Test on a real phone, not devtools emulation.

**Tap-for-evidence:** node → panel with label, type, state, plain-language confidence, and its evidence list — each `Evidence` row rendered by slicing `SourceEvent.content` with `spanStart/spanEnd` (the spans the NFKC index map exists to protect), with `occurredAt` shown (temporal honesty). The evidence view model **explicitly carries `authorship`** (joined via sourceEventId) — practitioner-authored evidence visibly marked non-conferring, never assumed. **COUNTERVAILING evidence renders visually distinct** (grammar-specified treatment) with the honest-scope note that polarity is model-assigned (gate §1.1). Hypothesis nodes with zero evidence show their provenance instead: "From your Human Design chart — nothing in your words yet confirms this." (Copy scoped per the matcher's honest v1 reach — see §3.) On a charged or contradicted ghost, the panel shows **which independently-extracted words did it** ("your chart guessed this; on June 3rd you said this") — this falls directly out of §3.1's derivation object.

**Realization events (v1 minimal):** when a pass materializes/charges nodes, the new/changed nodes animate in via cosmos v3 transitions and a small toast names them. The full ceremony choreography is post-pilot; the cut-line already covers degrading to static. (LAW 6 note: the animation celebrates *validated evidence events* only — never streaks, never variable-ratio surprise.)

## 3. The hypothesis matcher (`/src/engine/hypothesis-match/`)

The blinding invariant's completion: the **deterministic, post-gate** module that may see both worlds. After the writer persists a pass, the matcher compares newly validated EXTRACTED nodes/evidence against standing **LENS** hypotheses and updates hypothesis state. **LENS-only in v1 (A-2/D-R3):** BECOMING matching is owned by the gate's in-gate label-matcher (gate spec §7) and is not this module's business. Precedence across the whole pipeline, pinned: **gate own-provenance dedupe → gate becoming-label merge → post-gate lens matcher.** Since gate v1.7, the gate's dedupe cannot touch a LENS node (test 19), so this module is provably the only charging path for lens hypotheses.

- **Match rule (deterministic, versioned `matchRuleVersion`):** v1 = same **domain `type`** + same `ontologyKey` (exact key match only; no embeddings, no LLM similarity — logged as post-pilot; D-R4 makes the type comparison meaningful). On match: supporting evidence accumulates charge toward `HYPOTHESIS → ACTIVE`; COUNTERVAILING evidence (under the §1.1 guards — recurrence ≥2 distinct events in SOLO mode, or practitioner confirmation in SUPERVISED) → `CONTRADICTED`.
- **Honest v1 reach:** CONTRADICTED is structurally rare in v1 — a blinded proposer assigns polarity relative to the *extracted* node and cannot tag opposition to a hypothesis it cannot see; the realistic v1 path to CONTRADICTED is affirm-then-deny of the same key. The §2 copy reflects this; the real (semantic) matcher remains the §7.1 bundle item.

### 3.1 The charge carrier (A-1/D-R2 — how a match actually becomes state)

- **Evidence is LINKED, never copied (D-R2):** one span, one `Evidence` row, referenced twice. The matcher writes a link record (`HypothesisEvidenceLink`: evidenceId → hypothesis nodeId, matchRuleVersion, matchedAt) through the **graph writer** — the extracted node's rows stay intact and single-owner; no duplicate rows enter mass math.
- **Arithmetic is the gate's, imported:** the hypothesis's mass, confidence, and state are recomputed by calling the **gate's exported pure functions** (mass §6.2, confidence §6.3, `nextState` §6.4) over the merged evidence set (own evidence ∪ linked evidence). Reuse is mandated; reimplementation is banned — a duplicated threshold drifts on first tuning, and the drift is invisible while both modules' tests stay green.
- **Mode guard is structural:** the matcher consumes a versioned `MatcherConfig` carrying `mode: SOLO | SUPERVISED` (mirroring `GateConfig`) — the §1.1 rule that a single model-labeled COUNTERVAILING quote never auto-contradicts in SOLO is enforced by the same shape of code that enforces it in the gate.
- **Every write is stamped and replayable:** each transition persists `matchRuleVersion` + `massAlgorithmVersion` + `confidenceAlgorithmVersion` + `stateAlgorithmVersion` + `computedAt`, and every run persists a **`MatcherRun`** row (inputs: pass/run id, prior hypothesis states; outputs: links written, transitions made) — the derivation object that makes "why is this ghost ACTIVE" answerable and §5 test 7's "replays identically" assertable against production history. The schema's "nodes are never written except via the gate" banner gains its sanctioned second author here, in writing.
- The matcher **never creates nodes and never runs during extraction.** It reads persisted state and writes through the writer, strictly after the writer commits a pass; the proposer's next pass still never sees hypotheses (its `priorExtractedNodes` filter is untouched — and §5 test 7 now ASSERTS byte-identity of the proposer's serialized context before/after a matcher run, rather than stating it).

## 5. Tests

1. **Lens determinism keystone:** same chart JSON → byte-identical node set (labels, keys, order — the total order makes ties impossible), twice. Different `lensMapVersion` → allowed to differ. *(Pure-function test; no DB.)*
2. **Import idempotency (split from 1 per C-3):** re-import into the DB → no duplicates, upsert against `@@unique([userId, system, chartFingerprint])`; concurrent import attempts cannot double-mint.
3. **Ghost integrity:** every lens node persists with a domain type (never LENS — the DB CHECK is exercised), mass 0, HYPOTHESIS, confidence floor, chartImportId set — and the projection styles it ghost (snapshot test on the view model, not pixels). Ghost-budget cap holds at the config value.
4. **Projection purity:** `skyProjection` same input (including explicit `now`, `seed`, config) → same view model; no Date.now(), no randomness.
5. **Domain/rendering firewall:** property test — no field of the view model's layout output is ever written back through any writer path; type-level check that coordinate types can't enter domain modules; **schema assertion that no coordinate columns exist on domain tables** (migration 6 stays deleted).
6. **Span slice round-trip in the UI path:** evidence panel renders exactly `content.slice(spanStart, spanEnd)` for the non-ASCII fixtures (the gate's test 11, re-asserted where users actually see it), with `authorship` present and rendered.
7. **Matcher keystones:** exact type+key match links evidence and charges through the gate's arithmetic (mass > 0, ACTIVE, stamps present); near-miss key does NOT (no fuzzy creep); single COUNTERVAILING never contradicts in SOLO (negative guard) AND recurrence ≥2 DOES contradict (positive transition); unmatched stays SILENT; `MatcherRun` replay produces identical links, states, and stamps; **the proposer's serialized context is byte-identical before/after a matcher run** (blinding non-interference, asserted not stated). **Pipeline-level:** extracted evidence charges a lens ghost end-to-end (real wrapper → real gate → writer → matcher), per the evidence-semantics charter rule.
8. **Fallback completeness:** every node/edge/evidence reachable in the list view with keyboard only; list view content-parity property against the same view model; reduced-motion snapshot renders without transition calls; cosmos.gl methods queue until `graph.ready` (integration).
9. **Import failure + the match-rate canary:** API error → `status=error`, zero nodes, retry works, no partial sky. **Lens-confirmation eval case:** a synthetic journal written to confirm a known chart hypothesis flows pipeline→matcher to a charged ghost — makes SILENT-forever detectable and measures D-R1's population-level gradient per ontology version.
10. **WOUND veil:** a WOUND node in an INDIVIDUAL-role projection renders veiled (snapshot); full in SUPERVISED; veil copy comes from config; crisis-classification pathway provably independent of the veil flag.

## 6. Build order

Lens mapping + import (deterministic, testable today) → sky projection + view-model tests → **list view (in-milestone, LAW 5)** → cosmos.gl v3 integration on the Railway deploy (ghost sky live) → tap-for-evidence → hypothesis matcher. The ghost-sky milestone requires the first four.

## 7. Schema & contract deltas (A-5 — every carrier named with its owning migration)

**Landed in migration 6 (this round):**
- `PsycheNode.x`, `.y`, `.colorHint` dropped (domain/rendering firewall).
- DB CHECK `PsycheNode.type <> 'LENS'` (D-R4; `NodeType.LENS` deprecated-never-written in the contract, kept for migration cleanliness, removed later once nothing references it).

**Owned by the lens-lane build (migration 7, when §1 is built):**
- `ChartImport.status` (`ok | error`), `chartFingerprint`, `provider`, `lensMapVersion`; `@@unique([userId, system, chartFingerprint])`.
- `PsycheNode.lensMapVersion String?` (set only for provenance=LENS).
- Config keys: `lens.ghostBudget`, the lens map's priority ordering; the hypothesis confidence floor REUSES gate config `confidence.hypothesisFloor` (never duplicated).
- **Deletion cascade (LAW 8, schema-blocking half):** deleting a ChartImport archives its UNCHARGED lens nodes and severs the FK on CHARGED ones (provenance note retained on the node); the governance architecture around it is the §7.1 entry.

**Owned by the matcher build (migration 8, when §3 is built):**
- `HypothesisEvidenceLink` (evidenceId, nodeId, matchRuleVersion, matchedAt; unique per pair).
- `MatcherRun` (id, trigger pass/run id, matcherConfigVersion, matchRuleVersion, transitions JSON, createdAt).
- Contract types: `MatcherConfig { mode, matchRuleVersion, … }`, `HypothesisMatch`, `MatcherRunResult`; **practitioner-confirmation carrier** (`HypothesisConfirmation`: practitionerId, nodeId, direction, at) — specified here because §3 cites it as a CONTRADICTED trigger; until migration 8 lands it, SUPERVISED contradiction-by-confirmation is unreachable and the matcher must treat it as such (fail-closed, never pretend).
- Contract bump when these types land (v2.3).

**Renderer-owned (no domain migration):** `SkyViewModel` + `PersistedNodeView`/`PersistedEdgeView`/`projectionVersion` live in `/src/engine/sky-projection/` (rendering-side types, structurally unable to enter domain modules); `rendererConfig` (versioned: grammar constants, confidence bands, woundGate, fringe copy, brightness half-life).
